# Historical: Nexus CLI 3.5.0 — Engineering Brain Build

## Product north star

Nexus is the verification and reliability operating layer for any coding model. The model proposes; Nexus establishes repository context, constrains scope, executes through policy, verifies externally, records evidence, and refuses unsupported completion claims.

The flagship workflow remains:

```bash
nexus fix "repair the regression without changing the schema" \
  --budget-inr 20 --model auto --proof
```

## Sprint 0 — Release integrity and canonical runtime — Complete

- One canonical execution namespace and one canonical recovery namespace.
- No fake-success session path or shadowed module/package collision.
- Self-contained installed benchmark fixture.
- Artifact-bound test, benchmark, wheel, source-distribution, and architecture evidence.
- Physical source-layout, import-all, secret, and complexity gates.

## Sprint 1 — Repository Engineering Brain — Complete

- Repository Intelligence selects decisive files, symbols, callers, related tests, architecture layers, and repository tree hash.
- Explicit user-named paths are included even when the requested file does not exist yet.
- The runtime injects the engineering contract into planning and model context.
- Strict repair modes block before a model call when a safe mutation boundary cannot be established.

## Sprint 2 — Durable engineering memory — Complete

- Repository-local task memory records goals, constraints, non-goals, decisions, changed files, failures, verification state, and remaining work.
- Atomic writes, SHA-256 seals, sequence numbers, cross-process locks, and stale-writer rejection protect task state.
- Long-horizon phases are persisted as RESEARCH, PLAN, IMPLEMENT, VERIFY, REVIEW, COMPLETE, BLOCKED, or FAILED.
- Corrupt or tampered phase state fails closed rather than being silently recreated.

## Sprint 3 — Surgical editing authority — Complete

- Every mutation is checked beneath the model against permitted files and forbidden patterns.
- Changed-file and changed-line budgets are enforced before and after editing.
- Unplanned files require an evidence-backed scope-expansion reason and consume a bounded expansion budget.
- Secret, credential, environment, Git-internal, and Nexus-state paths remain prohibited by default.

## Sprint 4 — Senior-engineer planning discipline — Complete for controlled beta

- Planning begins with baseline reproduction, impact inspection, minimal coherent change design, targeted checks, regression checks, and final diff review.
- The plan critic surfaces missing tests, missing callers, risky architecture areas, explicit non-goals, and insufficient repository evidence.
- Existing typed planning contracts, dependency graphs, deterministic validation, acceptance criteria, and independent plan critique remain authoritative.

## Sprint 5 — Semantic verification — Complete for controlled beta

- Tests passing is necessary but not sufficient.
- Completion requires mutation evidence, external verification evidence, independent review when policy requires it, approved scope, and no unresolved failed evidence.
- Tests-only patches for production behavior are rejected.
- Acceptance criteria without mapped evidence produce PARTIALLY_VERIFIED rather than VERIFIED.
- Engineering-state integrity failures force BLOCKED or FAILED outcomes.

## Sprint 6 — Failure learning and self-correction — Complete for controlled beta

- Failure lessons are redacted, fingerprinted, append-only, fsynced, cross-process locked, and hash chained.
- Repeated failure signatures escalate from narrow reproduction to root-cause reconstruction and Ceiling escalation.
- Corrupt lesson logs refuse new writes and cannot be used as trusted model context.

## Sprint 7 — Matched-model proof gate — Complete

- `nexus benchmark compare-matched` requires identical task, model, source revision, and authorized budget.
- The gate measures verified success, uplift, false completion, regressions, budget compliance, cost, latency, and intervention metadata.
- Unmatched trials, insufficient samples, false completion, regressions, or budget violations fail the gate.

## Sprint 8 — Distribution and deployment qualification — In progress

Completed locally:

- source and installed architecture checks;
- wheel and source-distribution build;

- installed benchmark from an unrelated directory;

External evidence still required before release-candidate or Claude Code-equivalent claims:

- same-model direct-versus-Nexus uplift on at least two affordable models;

- false verified completion below the target with zero known false passes in the release corpus;
- long-horizon interruption, dirty-worktree, provider-chaos, and rollback qualification on real tasks.

## Current designation

Nexus 3.5.0 is a hardened controlled beta for supervised Verified Repair evaluation. The release contains stronger engineering discipline and measurable parity gates, but it does not claim proprietary-model intelligence equivalence or universal reliability without the external evidence above.
